Scale Architecture

Design for 10,000 audits per day, bursts of 500 concurrent requests, and a customer-facing response-time SLA.

Components and Data Flow

  1. Client calls POST /api/audit with a URL.
  2. CDN and WAF apply edge protections before traffic reaches the load balancer.
  3. Stateless API instances validate the URL, attach a request ID, check per-client rate limits, and read the audit cache.
  4. Cache hits return immediately with 200.
  5. Cache misses run synchronously while capacity is available, or return 202 with a job ID during bursts.
  6. Workers fetch target pages with timeouts, byte limits, HTML validation, and backpressure.
  7. Audit results are stored in Redis for the cache window and Postgres for durable history.

Queueing Strategy and State

A bounded Redis-backed queue such as BullMQ, or a managed queue such as SQS, absorbs traffic spikes without letting outbound fetches overwhelm API instances. Queue depth, oldest job age, and worker timeout rate decide autoscaling and load shedding.

  • Redis: shared cache, rate-limit counters, queue coordination.
  • Postgres: durable audit records, API keys, customer accounts, reporting.
  • Object storage: optional short-retention debug samples.
  • Observability backend: logs, metrics, traces, alerts.

Technology Decisions

Node.js API

Chosen for fast I/O-heavy URL fetching. Rejected a heavy framework stack because the assessment API surface is small and dependency-light code is easier to review.

Redis Cache and Limits

Chosen for shared low-latency state across API replicas. Rejected process memory only because it fails across multiple instances and resets on deploy.

Bounded Queue

Chosen to absorb 500-request bursts while preserving API latency. Rejected unlimited in-process promises because they can exhaust sockets and memory.

Postgres Metadata

Chosen for durable audit history and customer reporting. Rejected document-only storage because account, API key, and reporting data are relational.

Failure Modes and Mitigations

  • Slow target websites: enforce timeouts, response-size limits, redirect limits, per-host concurrency, and queue backpressure.
  • Redis outage: run managed HA Redis, alert on failures, degrade cache behavior, and fail closed for async queue work if required.
  • Burst exceeds worker capacity: autoscale on queue depth and oldest job age, cap queue length, and return structured 503 when capacity is exhausted.

Monitoring, Alerts, and Rollback

Monitor request rate, p95 and p99 latency, error-code distribution, cache hit ratio, Redis latency, active audits, queue depth, oldest queued job age, worker timeout rate, outbound fetch latency, CPU, memory, sockets, and event-loop delay.

Alert when p95 latency exceeds SLA, non-validation errors exceed 2%, queue age crosses SLA, Redis is unavailable, timeout rate spikes, or cache hit ratio drops sharply after deploy.

Rollback with immutable versions and blue/green or rolling deploys. Release to a small traffic slice, compare telemetry, route traffic back to the previous healthy version on alert, and keep migrations backward-compatible for at least one release.
